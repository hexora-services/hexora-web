# HEXORA V4 — რეგისტრაცია Firebase-ით

V3-ის კატეგორიები, ქვეკატეგორიები და ვიზიტის ფასიანი გამოძახების დემო შენარჩუნებულია. V4 ამატებს ნამდვილ ანგარიშებს ცალკე **account.html** გვერდით. საწყისი ვერსია **არ არის საჯარო გამოსაყენებლად მზად**.

## Firebase-ის გამართვა (თავიდანვე ახალი HEXORA პროექტი)

1. შედი https://console.firebase.google.com/ და შექმენი ახალი პროექტი, მაგალითად `hexora-services-app`. არ გამოიყენო Domino Georgia-ს ან CarDoc-ის არსებული Firebase.
2. **Build → Authentication → Get started → Sign-in method** — ჩართე **Email/Password**.
3. Authentication → Settings → **Authorized domains** — დაამატე `hexora-services.github.io` (ბოლო ნაწილში path `/hexora-web/` არ მიუთითო). შეიძლება შემოწმება ან ხელახლა გახსნა დასჭირდეს.
4. **Build → Firestore Database → Create database** — შექმენი Firestore და აირჩიე შესაბამისი რეგიონი (მოგვიანებით ცვლილება რთულია). თუ კონსოლი ტესტის რეჟიმს გთავაზობს, საჯაროდ არ დატოვო ღია წესები.
5. **Firestore Database → Rules** — მთლიანად ჩასვი `firestore.rules`-ის ტექსტი და დააჭირე **Publish**. წესები ჯერ გამოაქვეყნე და მხოლოდ ამის შემდეგ გამოიყენე რეალური რეგისტრაცია.
6. **Project settings → Your apps → Add app → Web (`</>`)** — დაარეგისტრირე საიტი და დააკოპირე `firebaseConfig`.
7. ფაილში `firebase-config.js` ჩაანაცვლე `PASTE_...` შესაბამისი მნიშვნელობებით. ეს მხოლოდ Firebase-ის საჯარო Web config-ია; არ ატვირთო Service Account JSON, API-ის საიდუმლო გასაღებები ან ბანკის პაროლები GitHub-ზე.
8. GitHub-ზე `hexora-services/hexora-web` რეპოზიტორიის მთავარ (`main` → root) საქაღალდეში ატვირთე `index.html`, `account.html`, `account.js`, `firebase-config.js`, `favicon.svg`. `firestore.rules` შეგიძლია ატვირთო საცნობაროდ, თუმცა უსაფრთხოებას ამოქმედებს Firebase Console → Rules → Publish, და არა GitHub-ში ფაილის არსებობა.
9. GitHub → **Settings → Pages → Deploy from a branch → main → /(root) → Save**. შემდეგ შეამოწმე `https://hexora-services.github.io/hexora-web/account.html`.
10. გააკეთე სატესტო ხელოსნის რეგისტრაცია, მიუთითე ფასი და შეამოწმე Firestore-ის `accounts` და `workerProfiles` კოლექციები.

### რა მუშაობს V4-ში

- Firebase Email/Password ანგარიშის შექმნა, შესვლა, გამოსვლა, პაროლის აღდგენა და ელფოსტის დადასტურების წერილი (Firebase კონფიგურაციის შემდეგ).
- ანგარიშის ორი ტიპი: მომხმარებელი ან ხელოსანი. როლი რეგისტრაციისას ინახება და ვებგვერდიდან არ იცვლება.
- ხელოსნის მონაცემების Firestore-ში შენახვა; ქალაქი, მომსახურება, ქვეკატეგორია, ვიზიტის ფასი 1–2000 ₾ და ონლაინ/ოფლაინ სტატუსი.
- ანგარიშის პირადი მონაცემები დაცულია Firestore Rules-ით. ხელოსანი `approved` ველს თავად ვერ ცვლის.
- ხელოსნის პროფილი `approved:false` სტატუსით იქმნება. მისი ადმინისტრატორის მიერ გადამოწმება და საჯარო კატალოგში ჩართვა მომდევნო ვერსიაში კეთდება.
- ძველი კატალოგი და დემო შეკვეთები უცვლელია და **არ არის** Firebase-ზე მიბმული.

### ჯერ არ მუშაობს

- სინქრონიზებული რეალური გამოძახებები, შეფასებები, GPS, გადახდები და საკომისიოს ჩამოჭრა;
- ადმინისტრატორის ნამდვილ უფლებებზე დაფუძნებული პანელი და ანგარიშის წაშლის სრულყოფილი პროცესი;
- რეალური ახალი ხელოსნების გამოჩენა ძველ `index.html` კატალოგში (V5-ის ნაწილი).

**უსაფრთხოების შესახებ**: `index.html`-ის **დემო**-ში ადმინისტრატორის ღილაკი მხოლოდ ბრაუზერში შენახულ სატესტო მონაცემებს ცვლის; რეალურ Firebase მონაცემებს ვერ ეხება. ნუ გამოიყენებ დემოს რეალური პირადი მონაცემებით.
